# Security Policy

## Supported Versions

The latest minor version of AtomicBinding receives security updates and bug fixes:

| Version | Supported          |
| ------- | ------------------ |
| 0.1.x   | Yes                |
| < 0.1.0 | No                 |

---

## Reporting a Vulnerability

The AtomicBinding team takes security vulnerabilities seriously. We appreciate your efforts to responsibly disclose findings.

### How to Report

If you believe you have found a security vulnerability in AtomicBinding, please **do not open a public issue**.

Instead, please report the vulnerability by contacting the project maintainers via GitHub Security Advisories:
1. Navigate to the **Security** tab of the repository (`https://github.com/SrishtiSonam/AtomicBinding/security`).
2. Click **Report a vulnerability** to open a private advisory.

### What to Include

To help us triage and resolve the issue quickly, please include:
- A description of the vulnerability and its potential impact.
- Clear steps to reproduce the issue (including sample payloads, schema definitions, or configuration).
- Any proposed remediation or patch, if available.

### Disclosure Timeline

- **Acknowledgment**: We aim to acknowledge receipt of your vulnerability report within 48 hours.
- **Triage**: We will investigate and verify the vulnerability and provide updates on resolution timeline.
- **Release**: Once a patch is developed and verified against all build gates, a security release will be published alongside an advisory.
